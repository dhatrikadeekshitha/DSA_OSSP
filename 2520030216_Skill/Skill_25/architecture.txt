4. SYSTEM CALLS
---------------

fork()
Creates a child process.

pipe()
Creates a unidirectional communication channel.

dup2()
Connects a pipe to standard input or standard output.

execvp()
Replaces the child process with the requested command.

waitpid()
Waits for child processes and obtains their exit status.

getrusage()
Obtains CPU and memory-related resource statistics.

gettimeofday()
Provides timestamps used to calculate execution time.

kill()
Sends a signal to a process.

close()
Releases file descriptors.


5. DESIGN DECISIONS
-------------------

- Maximum pipeline stages: 16.
- Each pipeline stage executes in a separate child.
- Pipes connect neighboring pipeline stages.
- Unused descriptors are closed to prevent resource leaks.
- Parent waits for all pipeline children.
- Background jobs are stored in a fixed-size job table.
- Exit codes identify successful and failed processes.
- Resource usage is obtained using getrusage().
- Execution time is measured using gettimeofday().
- Functional modules separate parsing, execution,
  monitoring and documentation.


6. PERFORMANCE ANALYSIS
-----------------------

The program measures:

- Pipeline execution time
- User CPU time
- System CPU time
- Maximum resident memory
- Page reclaims
- Page faults
- Voluntary context switches
- Involuntary context switches

These measurements help analyze the stability and
performance of large pipelines.


7. FAILURE HANDLING
-------------------

A pipeline failure is detected when a child:

- Returns a non-zero exit status, or
- Is terminated by a signal.

The final pipeline result is reported as:

SUCCESS
or
FAILURE.


8. RESOURCE CLEANUP
-------------------

The program closes all pipe file descriptors in
both child and parent processes.

The parent waits for all pipeline children.

Remaining background jobs are terminated when
the program exits.
